# 墨阅诊断日志

## 发给遇到 EPUB / TXT 无法打开的用户

1. 把开发者提供的诊断包解压到 Kindle 根目录，最终应出现 `extensions/moyue-diagnostics/menu.json`。
2. 启动墨阅，分别尝试打开一本 EPUB 和一本 TXT，记下现象，例如错误提示、白屏或退出。随后退出墨阅回到 Kindle。此时先采集日志，避免重启导致内存日志丢失。
3. 打开 KUAL → 墨阅诊断日志 →「1. 采集日志」。屏幕提示 `Saved` 后，日志保存在 Kindle 的 `moyue-diagnostics/report.txt`。
4. 开启 Wi-Fi，关闭飞行模式，在 KUAL 选择「2. 上传日志」，阅读提示后选择「同意发送到开发者服务器」。
5. 屏幕出现 `Uploaded. Report ID` 表示成功。把编号及 Kindle 型号、墨阅版本、失败现象发给开发者。编号也保存在 `moyue-diagnostics/receipt.txt`。

日志可能含书名、文件路径及已有日志中的错误信息。脚本读取三份墨阅日志的末尾、固件版本、应用来源说明、内存/磁盘与运行资源存在情况。账号配置、书库数据库和书籍正文不在采集列表。脚本会过滤含常见凭据关键词的日志行，但不能保证已有日志中的所有个人信息都被识别，上传前可以在电脑查看 `report.txt`。

若提示操作正在进行，请等上一轮结束。若上一次因断电或强制关闭中断，请重启 Kindle 后重新复现并采集，临时锁会随重启清除。

若提示失败，日志仍保存在 Kindle，可通过 USB 复制 `report.txt` 发给开发者。旧固件可能缺少 curl 或可用的 HTTPS 根证书，也可能受 Wi-Fi、防火墙或服务器临时凭证到期影响。勿关闭证书校验。没有出现新的成功提示时，旧的 `receipt.txt` 代表上一次上传。

## 开发者配置

源码目录只包含通用脚本。实际交付包需要在 `extensions/moyue-diagnostics/` 内放两个纯文本文件，每个一行。

- `endpoint.txt` 填写 HTTPS 接收地址，路径为 `/moyue-diagnostics`。
- `token.txt` 填写本次支持会话的随机上传凭证，至少 32 个字母、数字、下划线或连字符，与服务端一致。

这两个文件由目录内 `.gitignore` 排除。诊断包含临时上传凭证，请私下交给需要协助的用户。凭证到期后生成新凭证和新的交付包，同时更新服务端环境文件并重启本次独立服务。

接收端运行方式如下，环境文件保存在仓库外并设为 0600。

```sh
python3 scripts/diagnostics-server.py
```

必须设置 `MOYUE_DIAG_TOKEN`、`MOYUE_DIAG_DIR`。可设置 `MOYUE_DIAG_EXPIRES`（Unix 秒时间戳，默认进程启动后 24 小时）与 `MOYUE_DIAG_MAX_TOTAL`（默认 64 MiB）。部署时使用固定到期时间，避免服务重启延长凭证有效期。单次最多 1 MiB，服务仅监听 `127.0.0.1:11098`，由既有 HTTPS 代理转发该路径。日志以随机编号命名为 `<编号>.txt`，经服务器 SSH 查看。容量满时拒收，需管理员按支持需求归档日志后再接收。

仅在用户同意上传后运行，脚本不会主动连接用户设备。设备端需要用户操作一次 KUAL。
