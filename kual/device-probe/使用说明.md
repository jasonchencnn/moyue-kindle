# 墨阅设备信息采集与适配请求

适用于已越狱并安装 KUAL 的 Kindle。设备报告用于核对多机型适配所需的硬件与固件属性，也可以据此向开发者请求适配。

## 安装和使用

1. 解压交付ZIP到Kindle根目录，重新打开KUAL，选择「墨阅适配中心」。
2. 独立中文页面显示本机型号、固件、任务阶段、可用版本和安装进度。
3. 点击「上传并请求适配」，阅读报告范围后确认「同意上传」。
4. 页面自动更新本地状态，并每15秒查询服务器；「刷新状态」可主动刷新。
5. 安装包就绪后，「下载并安装匹配包」按钮启用。确认后后台下载、校验并首次安装。
6. 「退出适配中心」返回Kindle。后台上传或安装继续运行，重新进入页面可查看结果。

页面复用本机已安装的KOReader显示与触摸运行时，需要保留完整的 `/mnt/us/koreader`。请先正常退出KOReader，再从KUAL打开适配中心。启动器使用官方启动壳的临时副本完成屏幕交接与退出恢复，运行时设置保存在内存中。页面初次打开会在本机采集基本信息，确认上传后才联网。

上传中、请求失败、等待适配、安装包就绪、下载中和安装完成均有中文状态。网络失败时可以重试；下载阶段显示已下载大小。按钮会依据当前状态启用，后台任务与页面独立。墨阅安装完成后，请返回KUAL打开墨阅。

## 试装验证反馈

页面「反馈与日志」进入反馈页。反馈针对墨阅试装版本（预览版或试用版），分六类：正常、白屏、触摸、布局、无法启动、其它。设备端没有自由输入框，提交的正文只由本机的设备代码与固件拼出；需要写文字时用手机扫码。

- 「扫码反馈」先向服务器换一个只用于提交反馈的令牌，再把二维码显示出来。二维码里的地址固定在 `me.chen-cn.top`，令牌只能提交反馈，读不到设备报告和日志。原任务密钥不出现在二维码、地址、页面和日志里。
- 第一次提交分类反馈时先换令牌再提交；之后直接提交。设备端没有自由输入框，需要写文字时用手机扫码。
- 「上传日志」在确认后上传。日志只取墨阅应用日志（`/mnt/us/.aristotle/app.log`、`app.log.1`、`ui.log`、`/var/tmp/aristotle.log`）与适配中心自身日志（`task.log`、`install.log`、`center-*.log`）的有限尾部，上传前按行脱敏：带账号、令牌、密码、授权头、序列号的整行替换，长十六进制、MAC 与书籍路径替换成占位文字。不含书正文、账号令牌和完整序列号。上传上限 256 KiB，超出时先截断再上传并标注。
- 所有反馈操作都在后台执行，页面不等待，可随时离开再回来查看。失败时页面显示原因，可以直接重试。

## 两种入口包

`scripts/package-device-center.py` 打出两个包，文件顺序、时间戳和权限固定，同样的源码重复打包结果一致。

- `moyue-center-kual-<版本>.zip`：KUAL 扩展加 `documents/墨阅适配中心.sh`。
- `moyue-center-standalone-<版本>.zip`：同样的实现加 `documents/墨阅适配中心.sh` 与 `documents/墨阅.sh`，不需要安装 KUAL。

两个书库入口都带 `Name`、`Author`、`DontUseFBInk` 元数据，只调用共用的真实入口，进程用 `setsid` 脱离，重复启动有锁，失败会明确报错：

- `documents/墨阅适配中心.sh` 需要 `/mnt/us/koreader` 的 KOReader 运行时。缺运行时时明确报错退出，不假装打开。
- `documents/墨阅.sh` 需要本机已安装的墨阅应用（`/mnt/us/aristotle`）。没安装时明确报错退出，不假装打开。

打包器把这两条依赖写进清单和包内说明，缺少声明时拒绝打包。

## 适配服务接口

固定地址 `https://me.chen-cn.top/moyue/device/jobs`，不需要用户填写任何凭证。

- 提交：POST 报告正文，服务返回任务号 `id` 与任务密钥 `key`。
- 查询：GET 该任务地址，用 `Authorization: Bearer <key>` 取回阶段、进展、更新时间和可用安装包。
- 任务状态存在服务器上，与 KUAL 进程无关。关掉 KUAL 不会取消任务，重新打开用「查看适配进度」即可接着看。

阶段只有六种：`已就绪`、`等待适配`、`适配中`、`构建中`、`验证中`、`失败`。屏幕使用 ASCII 分行显示阶段、更新时间和版本。中文详情、下载地址和 SHA256 保存在 `moyue-device-probe/task.log`，也输出到命令行。匹配到安装包时记录可用版本、试用状态（预览版或试用版）、下载地址和 SHA256；没有匹配包时如实显示「等待适配」，不会编造构建进度。

## 首次安装、校验与恢复

安装包只接受 `https://me.chen-cn.top/moyue/downloads/*.tar.gz`，不跟随重定向。2.0.1起优先连接Oracle的8443独立下载端口，仍按原域名验证HTTPS证书，连接超时8秒，持续30秒低于1 KiB/s时回退。直连失败后通过原入口续传，连接超时30秒，最多3次回退尝试。每次下载最长30分钟，最大64 MiB。下载后先比对服务端 SHA-256，再逐项检查 tar 名单：只允许 `aristotle/` 和 `extensions/aristotle/`，拒绝绝对路径、`..`、反斜杠、控制字符、重复项、符号链接、硬链接和特殊文件。解压到 `moyue-device-probe/install`，校验应用二进制、数据、启动器、扩展配置和 VERSION，应用与扩展版本必须都等于服务端版本；再直接 source 包内 `aristotle/guard.sh` 校验机型和固件（不接受 `ARISTOTLE_FORCE`）。

只做首次安装：发现 `/mnt/us/aristotle` 或 `/mnt/us/extensions/aristotle` 已存在、墨阅正在运行、空间不足或目标/状态是符号链接时，直接拒绝且不改文件。两次 rename 前写 journal；若中途断电或失败，下次安装会把本次装出的目录按所有权标记移回暂存区，再重试。来源不明的目录不会被删除；回滚失败时保留 journal 和暂存数据，日志在 `moyue-device-probe/install.log`。安装状态在 `moyue-device-probe/install.txt`，不含任务号、密钥、URL 或 SHA256。

## 任务凭据

任务号与密钥保存在 `moyue-device-probe/task.txt`，文件权限 0600，目录 0700，写入用临时文件原子替换，遇到符号链接直接拒绝。

密钥只通过 curl 的标准输入传给服务器，不出现在命令行参数、设备报告和日志里。重启或重新打开 KUAL 后凭据仍在，可以继续查询。

## 采集内容和用途

报告包含设备代码、固件、内核、CPU 特性、内存、系统库文件名、framebuffer 属性、framebuffer 驱动与内核模块链接、设备树 model 与 compatible、过滤后的显示/输入/触摸内核消息、KOReader 运行时版本、输入设备能力、背光和电池节点。完整序列号会缩减成机型代码。账号、书库、书名、书籍正文、应用日志、Wi-Fi 和 IP/MAC 信息均在采集范围之外。

采集只读：没有 `/dev/fb` 写入，没有模块加载或卸载，没有 sysfs 写入，没有事件流，没有网络。驱动内建在核心里时，报告写「built into the kernel」，不会去尝试加载。

选择上传后，报告经 HTTPS 发送到开发者的 Oracle 服务器并私有保存。原始报告没有 HTTP 读取入口。报告在本机和服务器保留，后续由用户或开发者按测试需要归档或删除。

报告以 `MOYUE-DIAGNOSTICS-1` 和 `report-kind: device-probe-v1` 标识类型。输出文件权限为 0600，目录为 0700。每项按固定上限读取，过长字段会标注省略，总报告最多 30 KiB（服务端上限 32 KiB）。

## 后台行为

后台提交与安装都用 `setsid` 脱离 KUAL 进程组，关闭 KUAL 不会终止远端任务或安装。后台 worker 记录 `moyue-device-probe/task.log`、`install.log` 和安装状态。屏幕底部的 ASCII 状态由前台操作显示。「查看适配进度」会在安装过程中有界刷新阶段和已下载大小，结束后可再次进入查询。

同一时间只允许一个适配请求在跑，重复点「同意上传并请求适配」会被挡下并提示先查看进度。上一次任务残留的锁会按进程存活状态判定，进程已不在时自动清理。

## 缺失信息和后续验证

`[missing]`、`[unavailable]`、`[symlink ignored]` 表示该项未采到。部分固件缺少 sysfs 节点或 `fbset`，仍可生成报告。存在 `fbset` 时会读取其 `-i` 信息。

采集使用已有系统接口，运行时会用 `eips` 显示状态。适配仍需验证刷新命令、波形、触摸坐标、旋转、暖光和休眠恢复。报告中的机型属性作为这些验证的输入。

若出现「上一次适配请求还在进行」，先等上一轮结束或查看进度。若出现「查询失败」，任务凭据仍保留在本机，连上 Wi-Fi 后重新进入「查看适配进度」即可重试。若出现其他失败提示，请记录提示并回传给开发者。

## 开发者打包

`task.sh` 使用固定接口地址，不随包分发任何凭证。源码中的 `endpoint.txt` 和 `token.txt` 由 `.gitignore` 排除，只供旧版 `probe.sh upload` 兼容使用。公开交付 ZIP 不包含这两个文件。

接口地址只在测试根 `AGENT_TEST_ROOT` 下允许用 `MOYUE_DEVICE_API` 覆盖，设备上始终使用固定地址。上传流程沿用既有诊断服务的报告格式，凭证通过标准输入交给 curl。测试通过 `AGENT_TEST_ROOT` 使用合成设备目录与命令桩。

开发者命令与菜单对应为 `task.sh submit`、`task.sh status`、`task.sh collect` 和 `task.sh install`。`install` 只在显式确认后执行，调用 `install.sh URL SHA256 VERSION`；任务 id/key 不会进入安装参数或日志。
