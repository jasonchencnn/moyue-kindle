# 同步协议与兼容性

墨阅 Kindle 不是 Readest 的 fork，而是**实现 Readest 同步协议的独立客户端**。目标是：同一个 Readest 账号，在手机/桌面 Readest 与 Kindle 上读到同一位置、看到同一条笔记。

## 兼容的对象

| 对象 | 状态 |
| --- | --- |
| Readest 账号登录（邮箱 + 密码） | 已实现。默认走 Readest 官方认证中转 `https://auth-cf.readest.com`，地址可在设置中修改。 |
| Readest `/api/sync`（configs / notes） | 已实现拉取与推送；字段与合并规则对齐 Readest 的 `sync.ts`。 |
| Readest 云端书库列表与下载 | 已实现（列表缓存、流式下载、哈希校验）。 |
| 阅读进度 | 以 XPointer 存储；与 KOReader 同源，可直接互认。Readest 侧使用 CFI，由 Readest 的映射逻辑互通。 |
| 高亮与笔记 | 按 `id` 合并，逐条 `updatedAt` + `deletedAt` 墓碑；跨节点端点按"同节点精确、跨节点近似"处理。 |
| KOReader / KOSync | 进度通过 XPointer 互通；KOSync 接口本身不在本客户端范围内。 |

## 合并规则

- 标量字段（书名、作者、阅读设置等）按字段级 LWW，最后写入者胜。
- 笔记按 `id` 集合合并：同一 `id` 取较新的 `updatedAt`；删除写墓碑，墓碑优先，不会被旧记录复活。
- 进度使用独立时间戳，避免整行 LWW 互相覆盖；拉取到较新进度时，客户端会提示是否跳转，而不是静默覆盖当前阅读位置。
- 拉取/推送失败不影响本地阅读；网络恢复后增量重试。自动推送可在设置中关闭，关闭后手动操作仍可用。

## 认证与网络

- 登录使用邮箱 + 密码，经官方认证中转换成访问令牌；令牌刷新由账号会话统一管理，并发过期只刷新一次。
- 密码不写入日志、不进入 `Debug` 输出；本地只保存令牌与账号标识。
- 网络请求走显式策略：只允许配置的 API / 认证主机，默认官方地址；可配置自建地址，但当前版本不提供自建服务端。
- 响应体有大小上限（约 20 MiB），超出会报错。

## 已知限制

1. **TXT 不跨端**：TXT 进度与笔记只存本地。
2. **`book_hash` 不同只按比例同步**：不保证落到同一段落。
3. **超长文本节点（>约 8000 字）与 `<pre>` 首行**的 CFI/XPointer 映射可能偏一页；阅读进度本身不丢。
4. 统计同步、云端上传、设备配对、CFI 转换接口不在当前版本内。

## 数据与隐私

- 书籍文件默认只保存在本地 `documents/`；云端下载的书由用户显式发起。
- 同步只传输进度、阅读设置、高亮与笔记等元数据，不主动上传书籍文件。
- 账号密码、设备序列号、版权书籍内容不应出现在 issue、日志或截图中。
